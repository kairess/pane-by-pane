# 원작 조작 방식 조사와 웹·모바일 적용 분석

조사 대상: The Artisan of Glimmith (PC, Unreal Engine, 마우스+키보드, 컨트롤러/Steam Deck 지원). 출처는 문서 끝에.

## 1. 원작의 조작 체계

### 1.1 입력 모드 (좌측 패널, TAB / Shift+TAB로 순환)

| 모드 | 하는 일 |
| --- | --- |
| **칠하기(Paint)** | 빈 칸을 클릭·드래그해 색칠. region은 이미 칠한 칸에서만 자라난다. "스마트 브러시": 현재 region이 완성될 때까지 같은 색이 유지되어 색을 다시 고를 필요가 없다. 같은 칸을 반복 클릭하면 팔레트의 색을 순환. 지우기도 가능하고, **경계선도 지워진다**(이게 불만 대상). |
| **경계선(Border)** | 칸 사이 점선을 클릭·드래그해 금속 경계선을 놓는다. 색은 안 건드린다. |
| **메모(Notes)** | 보드 위에 자유롭게 펜으로 그림. 마우스 업에 저장, 메뉴를 나가면 지워진다(불만). 그릴 수 있는 영역을 넓히는 패치가 있었다. |
| **?** | 현재 퍼즐의 규칙 설명, 조작법 팝업, 퍼즐 ID. |

### 1.2 색

- 퍼즐마다 기본 2~3색 팔레트("Auto Palette")가 다르게 주어진다. 같은 색이 인접하지 않도록 알고리즘이 색을 고른다. 벽으로 region이 갈리면 두 쪽의 색조를 자동으로 다르게 바꾼다.
- 팔레트 커스터마이즈(색별 켜기/끄기, 전체 무지개)가 있으나 리뷰는 "손이 많이 간다"고 평가.
- 색은 논리적 의미가 없다. 완성 판정은 색이 아니라 **분할**로 한다.

### 1.3 완성 판정 (개발자 설명)

두 가지 방법을 모두 인정하고, 둘 중 하나가 맞으면 자동으로 완성된다.

1. **경계선을 전부 그리기**: 색칠은 필요 없다. 다만 그린/안 그린 경계선에 오류가 없어야 한다.
2. **모든 region을 색칠하기**: 색칠된 region마다 경계선을 두른 상태가 정답인지 확인한다. 색이 다른데 붙어 있으면 자동으로 합쳐 본다.

부작용: 경계선 하나를 놓는 순간 퍼즐이 "먼저" 풀려 버리는 경우가 있어 버그 보고가 있었다. 개발자는 의도된 균형이라고 답했다.

### 1.4 보조 기능과 단축키

| 기능 | 조작 |
| --- | --- |
| region 둘레에 경계선 한 번에 두르기 | Shift+클릭 (region), 가운데 클릭 (연결된 영역 전체) |
| 넓이 카운터 | Ctrl을 누른 채 마우스 오버 → 연결된 영역의 칸 수 표시 + 영역 하이라이트 (컨트롤러 D-pad 위) |
| 되돌리기 / 다시 실행 | Z (마우스4) / D-pad 오른쪽 |
| 재시작 | R |
| 진행 확인 (Check Progress) | 버튼. 설정에서 숨길 수 있음("자꾸 누르는 사람용") |
| 오류 표시 (Show Errors) | 항상 / 확인 시 / 끄기 3단계. 규칙 위반 칸을 하이라이트 |
| 색 선택 | 숫자 키 (9 = 물결표 별칭) |
| 메모 지우기 | D-pad 왼쪽 |

- 터치 입력을 지원하고, 컨트롤러는 커서를 조이스틱으로 옮기는 방식이라 "정밀도가 떨어진다"는 평가.
- 커서가 소프트웨어 렌더링이라 클릭 정확도가 떨어져 하드웨어 커서로 바꾼 패치가 있었다. 작은 격자에서 정확한 클릭이 중요하다는 방증.
- 점선(칸 경계) 가시성 개선 패치: 칸이 작아질수록 점선 개수를 8→7→6으로 줄여 굵기를 유지.

### 1.5 커뮤니티가 겪는 마찰 (Steam 토론)

- 모드 전환이 잦다. "경계선이 아님(확실히 연결됨)"을 표시할 X 마크가 없어서 메모 모드를 오가야 한다.
- 칠하기 모드에서 경계선이 같이 지워진다. 경계선 모드에서는 색을 못 지운다(비대칭).
- 정답이 뻔한데 경계선을 일일이 그려야 완성 판정이 난다 → "현재 영역 전체에 경계선 두르기" 버튼 요청. 개발자는 "어려운 퍼즐일수록 풀면서 경계선을 놓는 습관이 중요하다"며 보류.
- Shift+클릭의 반대(경계선 일괄 제거)가 없다.
- 1칸짜리 region을 하나씩 칠하는 것이 지루하다. region 단위 지우개가 없다.
- 메모가 퍼즐을 나가면 사라진다. 세이브 스테이트(가지 탐색용)가 없어 "색을 바꿔 칠하고 Z로 되돌리는" 우회를 안내.
- 팔레트 설정이 번거롭고, 같은 색이 인접해 보이는 문제가 초기 최다 불만이었다.

## 2. 우리(웹·모바일) 관점의 분류

전제: 손가락 입력(정밀도 낮음, 호버 없음, 수정자 키 없음), 세로 화면, 한 손 조작.

### 2.1 그대로 가져올 것

| 항목 | 이유 |
| --- | --- |
| **분할이 정답, 색은 표현** | 이미 엔진이 edge 기반. 완성 판정을 색과 무관하게 할 수 있다. |
| **완성 판정 두 갈래(경계선 완성 or 색칠 완성) 자동 인정** | 플레이어가 선호하는 방식을 강요하지 않는다. 우리 UI는 지금 경계선만 있으니 색칠 완성도 인정하도록 확장. |
| **스마트 브러시**: 한 번 칠하기 시작한 region은 드래그로 이어 칠하고, 새 빈 칸을 탭하면 새 색이 자동 배정 | 모바일에서 색 고르기 UI를 없애는 핵심. 색 팔레트를 화면에 둘 필요가 없어진다. |
| **인접 region은 다른 색조 자동 배정, 벽으로 갈라지면 재배색** | 지금 보드의 region 채색과 같은 발상. 색조 선택 알고리즘만 보강. |
| **넓이 카운터** | 매우 유용. 다만 Ctrl+호버가 아니라 "탭 후 잠깐 표시" 또는 "길게 누르기"로. |
| **되돌리기/다시 실행, 재시작** | 필수. 화면 상단 고정. |
| **오류 표시 3단계(항상/확인 시/끄기)** | 우리 엔진의 `verify`와 부분 상태 전파로 규칙 위반을 즉시 알 수 있다. 기본은 "확인 시". |
| **? = 현재 규칙 설명** | 이미 패널에 있음. 모바일에서는 시트로. |
| **점선 가시성을 격자 크기에 맞춰 조정** | 작은 화면에서 더 중요. |

### 2.2 버릴 것

| 항목 | 이유 |
| --- | --- |
| **모드 전환(칠하기/경계선/메모) TAB 순환** | 모바일에서 모드 전환은 가장 큰 마찰. 한 화면 안에서 제스처로 구분해야 한다. |
| **수정자 키 조합(Shift+클릭, Ctrl+호버, 가운데 클릭)** | 터치에는 없다. 길게 누르기와 두 번 탭으로 대체. |
| **자유 펜 메모** | 손가락으로 작은 격자 위에 글씨는 불가능. 대신 구조화된 표기(X 마크, 후보 점)로 대체. |
| **팔레트 커스터마이즈, 숫자 키 색 선택, 색 순환 클릭** | 색이 의미가 없으니 자동 배색으로 충분. 원한다면 설정에 "색약 팔레트" 하나만. |
| **컨트롤러 커서** | 해당 없음. |
| **소프트웨어 커서 문제, 3D 월드 카메라, 플린스 탐색** | 우리는 보드만 있다. 세계 탐색은 나중 문제. |

### 2.3 고쳐서 적용할 것

| 원작 | 문제 | 우리 방식 |
| --- | --- | --- |
| 칸 사이 점선을 정확히 클릭해 경계선 | 손가락으로 점선 맞추기 어려움. 지금 우리 UI는 셀 크기의 30%를 히트 영역으로 쓰지만 5×5 이상에서 불안정 | **셀 위를 드래그**해 지나간 칸들을 "같은 region으로 잇기"(내부 edge = JOIN), 두 셀 사이를 **가로질러 짧게 긋기**로 경계선. 즉 경계선을 점 찍는 게 아니라 선을 긋는 동작으로 인식. 히트 영역은 셀의 중앙 40%는 칠하기, 바깥 30% 띠는 경계선으로 나눈다 |
| 칠하기 모드에서 경계선이 지워짐 | 비대칭·실수 유발 | 경계선은 경계선 제스처로만 지운다(같은 자리에 다시 긋기). 칠하기는 색만 건드린다 |
| "확실히 연결됨" 표시가 없음 | 메모 모드로 우회 | 경계선 자리를 **길게 누르면 X 마크**(JOIN 확정). 엔진의 3상태(UNKNOWN/JOIN/WALL)를 그대로 노출. 완성 판정에는 영향 없음 |
| Shift+클릭 = region 둘레 경계선, 가운데 클릭 = 연결 영역 둘레 경계선 | 수정자 키 | 칠해진 **region을 두 번 탭**하면 둘레에 경계선 일괄. 한 번 더 두 번 탭하면 일괄 제거(원작에 없던 반대 기능) |
| 1칸 region을 일일이 칠하기 | 지루함 | 경계선으로 둘러싸인 영역은 자동으로 채색(색칠 완성 판정과 일관). "현재 경계선 기준으로 전부 채우기" 버튼 제공. 개발자가 보류한 기능이지만 모바일에서는 클릭 수 절감이 더 중요 |
| Ctrl 호버 넓이 카운터 | 호버 없음 | 칸을 **길게 누르면** 그 연결 영역의 칸 수를 크게 띄우고 영역을 하이라이트 |
| Check Progress 버튼 + 오류 하이라이트 | 남용 우려로 숨김 옵션 | 완성은 자동 판정. 오류 표시는 설정(항상/확인 시/끄기), 기본 "확인 시"에 버튼 하나 |
| 메모가 퍼즐 이탈 시 소실 | 불만 | 보드 상태(경계선, X, 색)를 localStorage에 자동 저장. 다시 열면 그대로 |
| 세이브 스테이트 요청, "색 바꿔 칠하고 Z로 되돌리기" 우회 | 가지 탐색이 번거로움 | **가정 모드**: 버튼을 누르면 이후 입력이 반투명으로 쌓이고, "확정" 또는 "버리기"로 한 번에 처리. 우리 논리 solver의 what-if와 같은 개념이라 힌트와도 연결 가능 |
| 힌트 = 규칙 설명과 오류 표시뿐 | 막히면 정답 보기 외에 방법 없음 | 논리 solver의 다음 추론(technique 이름 + 대상 edge)을 단계별 힌트로. 지금 UI의 "정답 대비 차이" 힌트를 대체 |
| 터치 지원은 있지만 "마우스가 가장 깔끔" | 격자가 작다 | 세로형 보드(6×8)를 기본으로, 셀 최소 44px 확보. 큰 보드는 두 손가락 핀치 줌 + 드래그 이동 |

### 2.4 정리: 우리 조작 규칙 초안

- **셀 탭**: 새 region 시작(자동 색). 이미 칠한 칸이면 그 색을 "현재 붓"으로.
- **셀 드래그**: 지나간 칸들을 현재 붓 색으로 잇기. 경계선을 가로지르면 무시.
- **셀 두 번 탭**: 그 칸의 색 지우기. 칠한 region 두 번 탭은 둘레 경계선 토글.
- **셀 경계를 가로질러 긋기 / 경계 띠 탭**: 경계선 토글.
- **경계 길게 누르기**: X 마크(연결 확정) 토글.
- **셀 길게 누르기**: 넓이 카운터.
- 상단 바: 되돌리기, 다시 실행, 가정 모드, 오류 확인, 힌트, 규칙(?).
- 완성: 경계선 완성 또는 색칠 완성 중 하나를 만족하면 자동 판정, 진동·애니메이션.

첫 구현 우선순위: (1) 스마트 브러시 칠하기 + 두 갈래 완성 판정, (2) 경계선 긋기 제스처 정리와 X 마크, (3) 길게 누르기 카운터, (4) 자동 저장, (5) 가정 모드와 논리 힌트.

**구현 상태 (2026-09-13)**: (1)~(5) 모두 `src/web/`에 구현. 경계선은 "경계 띠 탭·드래그"로 통일했고 "가로질러 긋기"는 칠하기 드래그와 충돌해 넣지 않았다. 두 번 탭과 region 둘레 벽 일괄(원작의 Shift+클릭)은 없앴다. 오작동이 잦아서, 벽은 경계를 한 번에 하나씩 탭해서만 그리고 지운다(경계를 따라 드래그하는 동작과 길게 눌러 X 표시하는 동작도 없앴다). 칠한 칸을 탭하면 그 칸이 지워진다(원작의 칠하기 모드와 같음). 오류 표시는 정답이나 solver 추론과 비교하지 않고, 플레이어의 표시가 룰을 명시적으로 어긴 경우만 칸에 검붉은 빗금으로 보여준다(벽으로 닫힌 영역이 너무 작음·기호 누락, 칠한 영역이 너무 큼·숫자 둘·기호 중복, 확정 영역의 정확 비교, 마커를 가로지른 칠하기). 정답과 다르지만 아직 룰을 어기지 않은 벽은 표시하지 않는다. 힌트는 플레이어의 표시를 기준으로 가장 싼 추론(없으면 what-if)을 기법 설명과 함께 보여준다.

**힌트 재설계 (2026-09-13)**: 힌트는 3단계다. ① 어디를 볼지(관련 구역을 주황색으로 칠하고 "숫자 6이 있는 구역 근처를 보세요"), ② 무엇이 따라오는지와 이유(경계선이면 그 자리를 주황 굵은 선, 같은 구역이면 넣어야 할 칸을 점선 테두리로 표시하고 "…을 합치면 규칙에 어긋납니다. 이 사이는 경계선입니다" 같은 설명), ③ 적용(버튼이 "힌트 적용"으로 바뀌고 누르면 대신 그려 준다). 같은 난이도의 추론이 여럿이면 플레이어가 마지막으로 만진 칸에서 가까운 것을 고른다. 표시 중 정답과 어긋나는 것이 있으면 추론 대신 가장 먼저 만든 잘못된 표시를 빨간 점선으로 짚어 준다(힌트는 플레이어가 요청한 것이므로 정답을 참조하지만, 자동 오류 표시는 여전히 정답을 참조하지 않는다).
