## 이번에 바뀐 것

### 1. 홈 화면 바로가기 (PWA manifest)
- `public/manifest.webmanifest`, `public/icons/`, `index.html`의 `<link rel="manifest">`·아이콘·`theme-color`.
- `start_url`·`scope`·`id`가 모두 `./`라서 퍼즐 해시(`#w=6&…`)가 붙은 상태에서 홈 화면에 추가해도 루트로 열리고, 루트는 마지막 창을 복원합니다.

### 2. 한 셀에 기호 하나 (`src/engine/generator/clues.ts`)
- 셀 단서(장미창 기호 → 폴리오미노 → 넓이의 수 순)가 같은 셀을 쓰지 않습니다.
- 대가: 직사각 판 + 고정 경계선 없음 + 넓이의 수 + 장미창은 기호 셀의 숫자가 빠져 유일해 검사가 자주 실패합니다(7×7 4초, 8×8 9초, 9×9 기호 4개는 실패). 앱 기본값(비정형 창 + 고정 경계선)에서는 문제없습니다. 장미창 기호 재배치 8회(`generate.ts`의 redeal 루프)로 완화했습니다.

### 3. 표식(쌍둥이·닮지 않은 둘) 글리프 (`src/web/board.ts`)
- 폰트 글리프 대신 선으로 그려 원 중심에 맞췄습니다. 폰트의 수학 축 때문에 위로 떠 보이던 문제.

### 4. 난이도 측정 재설계 (`src/engine/logical.ts`)
- **lookahead 기법(3등급)**: 반대로 놓으면 규칙 검사가 즉시 실패하는 엣지를 가정이 아닌 직접 추론으로 처리. 예전에는 가정의 37%가 이런 경우였습니다.
- **가정 등급을 내용으로**: 모순까지의 라운드 수가 아니라 가정 안에서 확정된 엣지 수(≤3 짧음, ≤10 연쇄, >10 깊음).
- **점수** = 최고 등급 + 가정 비용 합 + 0.2×직접 추론 사슬(격자 크기 보정). 별 경계 `[3.5, 5.5, 8, 10.5, 14, 18]`. 대략 3★=짧은 가정 하나, 5★=깊은 가정 하나, 7★=깊은 가정 둘 이상.
- 힌트 문구: `src/web/i18n.ts`의 `lookaheadWall/Join`, `technique.lookahead`.

### 5. 난이도를 "요청"으로 만드는 생성기 (`src/engine/generator/generate.ts`)
- 같은 정답으로 지우는 순서를 바꿔 최대 8번(`ordersPerSolution`) 최소화한 뒤 새 정답으로. 정답 하나가 순서에 따라 2~7★가 나오므로 여기가 분산의 원천입니다. 결과가 반복되면 즉시 새 정답으로.
- 목표 하한 3★ 이상이면 4개 묶음 제거를 건너뛰고 낱개로 지웁니다(무작위 낱개가 시간당 7★ 적중률이 가장 좋았음. 유도·전수 탐욕은 느려서 제외).
- 목표 미달이면 `missed: true`와 함께 가장 가까운 퍼즐을 돌려주고, 웹은 "요청한 난이도가 아닙니다" 대화상자, CLI는 표시를 붙입니다.
- 전체 단서로도 상한을 넘는 요청(1★ 등)은 상한을 그 값으로 올려 "가능한 한 쉬운" 창을 만들고 미달로 표시합니다.

### 6. 구역 넓이 설정 제거 → 자동 (`autoSizeBand`)
- 웹 입력란을 없앴습니다. 판 크기와 목표 별로 범위를 정하고(6×6 3~6, 8×8 3~7, 어려우면 위로, 쉬우면 상한만 아래로) 정답마다 조금 흔듭니다. 하한은 3 미만으로 내리지 않습니다(2칸 구역끼리 다시 짝지어져 유일해가 깨짐). 작은 판은 구역이 넷 이상 나오도록 누릅니다.
- 옛 공유 링크의 `min`·`max`는 그대로 읽습니다. CLI `--min/--max`는 주면 우선.

### 7. 표식 전용 퍼즐 (쌍둥이·닮지 않은 둘·넓이 구분만)
- 원작 스크린샷(4×4, 굵은 납선 5개, δ 둘, Ⅱ 하나)을 엔진에 넣으면 해가 하나입니다. 유일성은 "구역이 작아 어떤 쪼개기도 표식을 깨뜨림"에서 나옵니다.
- 그래서 벽 모드에서 넓이 규칙이 없으면 구역을 1~3칸(넓이 구분은 1~4, 가끔 +1)으로 만듭니다(`markerOnly`). 측정: 비정형 판에서 "벽 전부 + 표식 전부"가 정답을 고정하는 비율이 1~3칸이면 절반, 1~5칸이면 0.
- 벽 모드의 최소화 순서: 어려운 목표(하한 3★ 이상, 표식 전용 제외)는 벽을 먼저(정답당 한 번), 그 외에는 단서를 먼저 지우고 벽을 다듬습니다. 먼저 지우는 쪽이 사라지고 남는 쪽이 퍼즐을 떠받칩니다. 벽은 쉬운 정보, 표식·기호는 어려운 정보.
- 웹의 "단독 불가" 안내(`warnCannotOutline`)는 제거했습니다.

### 8. 넓이 구분·장미창 단독 모드 (`partition.ts`, `generate.ts`)
- `growOnce`가 넓이 구분일 때 이웃과 다른 크기를 고릅니다. 7×7에서도 즉시 나옵니다.
- 장미창 단독 모드: 끝 칸이 기호 수보다 많은 구역은 분할 단계에서 다시 키웁니다(`maxTips`). 하한은 기호 수 k. 장미창 단독도 벽 모드를 거칩니다(직사각 판의 2×2 도미노 대각 기호 문제를 벽 하나가 풉니다).

### 9. UI 세 가지 (`src/web/board.ts`, `src/web/model.ts`)
- **칠한 칸 두 번 탭**: 그 구역 둘레에 경계선 일괄. 이미 다 둘러져 있으면 제거. 첫 탭의 지우기는 되돌리고 진행합니다(`lastErase`, 320ms).
- **길게 누르기**: 칠한 칸이면 그 구역, 빈 칸이면 벽·색칠에 막히지 않고 이어진 빈 칸의 수(`PlayerState.areaOf`).
- **오류 빗금**: 단서가 있는 칸은 가장자리 띠로만 그려 숫자·기호가 보입니다.
- 헤드리스 크롬에서 실제로 눌러 확인했습니다(`scripts/ui-drive.mjs`).

마지막 전체 검사(scripts/sweep.ts)는 세션이 끊겨 끝까지 돌지 못했습니다. 직전 검사와 개별 진단으로 확인된 것:

| 조합 | 상태 |
|---|---|
| 직사각 판의 도형 창고 단독 | 원래부터 불가(2×2 창고 외 타일링 비유일). 비정형 창 필요 |
| 쌍둥이 + 넓이 구분 | 논리 모순. 앱이 즉시 안내 |
| 표식 전용 6~7★ | 구역이 작아 대체로 3~5★. 미달 안내와 함께 5★ 반환, 6×6 기준 15~40초 |
| 폴리오미노 단독 높은 별 | 6×6 천장 2~3★. 9×9 7★ 요청은 몇 분 |
| 직사각 + 경계선 없음 + 넓이의 수 + 장미창 | 7×7 4초, 8×8 9초, 9×9 기호 4개 실패 (2번 항목) |
| 4×4처럼 작은 판의 7★ | 대부분 미달(정상: 판이 작아 어려워질 수 없음) |
